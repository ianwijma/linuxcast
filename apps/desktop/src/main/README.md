# Resident shell (F1-02)

`index.ts` starts the product Electron main process. The coordinator's build bundles it as `dist/main.cjs`, bundles `../preload/index.ts` as `dist/preload.cjs`, and supplies `dist/renderer/` plus `dist/assets.json`. The manifest is the exact list of packaged HTML, JavaScript, CSS, image and font assets. Only `index.html` is an HTML entry point. This does not depend on the launcher feasibility harness.

The primary process owns one resident launcher. No arguments and `--toggle` toggle it; `--show` opens it; `--quit` stops the application. A secondary invocation passes a validated command through Electron's single-instance lock. Links accept exactly `linuxcast://launcher/show` or `linuxcast://launcher/toggle`. They cannot execute commands, supply content or quit the application. Packaging must register the external scheme in the desktop entry; this module does not change user protocol associations itself.

Closing or hiding the launcher keeps the resident process alive. Destroyed renderers are recreated only after a subsequent explicit invocation. A single ordinary show/focus request never claims compositor activation succeeded: state reports observed focus, and `launcher-focus-unconfirmed`/`select-linuxcast-window` supports a visible manual recovery explanation. Wayland uses ordinary show without X11 focus/restore methods. There is no tray dependency, forced placement, implicit autostart, global shortcut registration or privileged input activation in this foundation.

`startResidentShell({ resourcesDirectory, createServices })` calls the optional service factory once, after primary-instance ownership, Electron readiness and resource/security setup. The factory returns trusted handles synchronously; each owns any asynchronous startup and cleanup. Both `stop()` and `terminate()` resolve only when owned resources are closed and child exit is verified. Quit gives graceful stop five seconds, then termination/verification one second. Failed or unverified termination produces a fixed operational error and nonzero exit. The production entry wires the storage owner and workflow services through this factory. Never create those owners before acquiring the instance lock.

All renderer content comes from `linuxcast-app://shell/` through the packaged asset allowlist. The session denies network outside those exact assets, permissions, capture and downloads. The web contents deny navigation, redirects, child windows, webviews and unload vetoes. Sandbox, context isolation, disabled Node and web security are explicit. The preload fails closed if sandbox/isolation are absent, exposes only the shared named shell API, validates returned data and strips Electron event objects. Every main request validates exact web contents, main-frame identity, URL and the entire versioned payload. Errors contain fixed operational text; URL arguments, contents and exceptions are never logged.

## Validation and remaining acceptance

Task: `docs/implementation/tasks/F1-02.md`. Normative boundaries: architecture overview/security/Linux integration and implementation testing-release. Applicable design sections: shell and navigation, states and motion, accessibility, review gate; dimensions/colours derive from the shared tokens. The renderer's Escape hierarchy, keyboard navigation, focus restoration and dark/light accessible states belong to the coordinated shared renderer integration.

- AC01: deterministic tests exercise packaged path restrictions, symlink escape, CSP, permissions, navigation, IPC sender/frame/payload rejection and the narrow preload. These are logic and mocked Electron boundary tests, not proof from a running renderer.
- AC02: deterministic tests cover single-instance dispatch, malformed links, two toggles during startup, resident hiding, explicit Quit and renderer recovery. Actual installed desktop invocations remain required.
- UI: shared renderer integration, affected-state screenshots, actual keyboard/screen-reader checks and the supported GNOME/KDE Wayland/X11 matrix remain outstanding. This foundation does not inherit acceptance from spike screenshots.
- PRIVACY: test values are synthetic; error/log checks reject reflective private payloads and event-object exposure. No real user contents, profiles, credentials or screenshots are collected.

Coordinator test mapping should include `commands.test.ts`, `assets.test.ts`, `security.test.ts`, `ipc.test.ts` and `../preload/api.test.ts` in `test:security -- F1-02`; `lifecycle.test.ts` and `shell.test.ts` in `test:unit -- F1-02`. Deterministic main tests use an Electron adapter. The mapped production integration tests separately launch actual sandboxed Electron on a private Xvfb display; this does not establish supported native sessions or assistive-technology acceptance. Run the full repository typecheck and lint as well.
