# L1-02 native GIO application launch and HTTP(S) handoff

`applications.rs` implements the one-shot `linuxcast-platform applications` protocol. The coordinator supplies binary routing and the main-only child adapter. This increment discovers installed desktop entries, dispatches their primary action, and provides an explicit HTTP/HTTPS default-handler handoff. It does not implement desktop Actions, custom URI schemes, file/argv/shell actions, run history, permission approval UI, or the complete L1-02 acceptance scope.

The helper reads one JSON line (at most 64 KiB) followed by EOF. It returns one bounded JSON reply (at most 1 MiB). Unknown fields, null optional cursor, unsupported version, invalid IDs and fingerprints fail closed. Titles/descriptions are byte-bounded. IDs are sorted by UTF-8 byte order, unique, and paginated strictly after the cursor. More than 10,000 GIO catalogue entries yields `catalogue-too-large`; the coordinator can impose a smaller aggregate provider bound. GIO itself loads its native catalogue before this count is applied; the main adapter also owns a process deadline.

Discovery uses `g_app_info_get_all`, checks desktop object type and `should_show`/Hidden, and returns only bounded public display metadata plus a SHA-256 fingerprint. A fresh `g_desktop_app_info_new` at launch repeats GIO's executable/TryExec validation and visibility checks. Fingerprints include the desktop identity, source filename, parsed command/name/icon and display properties, and launch-relevant keys including Exec, TryExec, Path, Terminal, DBusActivatable, visibility and startup properties. Launch uses that loaded object after checking the requested fingerprint. It is not a signature of the executable binary or a sandbox for installed applications; same-user modifications after validation remain outside an atomic filesystem snapshot.

Exec quoting, field substitution, terminal handling and D-Bus activation belong to GIO. The helper accepts no command string, arbitrary file path or argument array. The main process must supply its reviewed minimal desktop-launch environment, excluding provider keys. Application and HTTP(S) dispatch share `g_desktop_app_info_launch_uris_as_manager_with_fds` with `/dev/null` for stdin, stdout and stderr; spawn flags do not retain other descriptors. The shared session connection is flushed before this one-shot process exits. Success means GIO accepted dispatch, not application startup completion. D-Bus service availability, real terminal launch and desktop focus still require integrated target-session validation.

The separate `open-url` operation accepts only `{protocolVersion:1, operation:"open-url", url}`. Main supplies the shared URL schema's ASCII `URL.href`. Native independently caps the URL at 8192 bytes, requires explicit lowercase `http://` or `https://`, refuses literal whitespace/control/backslash, credentials/userinfo, malformed percent escapes and missing/invalid hosts or ports. It refuses ambiguous noncanonical authorities (encoded/uppercase hosts, alternate numeric IPv4, empty/zero-padded/default ports); canonical IDNA, IPv4, bracketed IPv6 and custom ports 0–65535 are supported. Strict `g_uri_parse` uses `G_URI_FLAGS_ENCODED` to validate without decoding URL components or repairing input. Valid escapes, including encoded control and non-UTF-8 octets, remain literal URI data. No DNS lookup, fetch or host-network authorization occurs here.

Each request looks up the current scheme default with `g_app_info_get_default_for_uri_scheme`. A missing handler, non-URI handler or implementation other than `GDesktopAppInfo` returns `unavailable`. A valid default need not appear in launcher discovery (a browser with `NoDisplay=true` can still be the configured handler). The original validated URL is one URI in a borrowed one-node list; it is not reserialized, interpreted as shell syntax, split into arguments or passed to `xdg-open`. GIO dispatch/flush failure returns only `launch-failed`; this does not prove whether an external effect occurred and must not be automatically replayed. Invalid input returns only `invalid-request`. No raw URL, filename or GError is returned in failures.

## ABI and ownership

Bindings were checked against installed GLib/GIO 2.72.4 public headers (`gio/gappinfo.h`, `gio/gdesktopappinfo.h`, GLib URI/spawn/checksum headers), installed GIR ownership documentation and upstream source. `gboolean`/flags use C integers; `GType`/`gsize` use pointer-sized integers for the supported amd64 target. GIO discovery list entries and default-handler results are owned object references. Local RAII guards release every list/reference, allocated string and GError; getter strings and icons are borrowed only while the owning object is alive. A separate `OwnedUri` guard releases `GUri` with `g_uri_unref`, never `g_object_unref`. The one-node URI list and its CString are borrowed only across synchronous dispatch and are not freed as object lists. No raw GError, filename, Exec or environment is returned or logged.

Primary sources:

- [GIO get_all ownership and visibility](https://docs.gtk.org/gio/type_func.AppInfo.get_all.html)
- [Manager launch with explicit standard streams](https://docs.gtk.org/gio-unix/method.DesktopAppInfo.launch_uris_as_manager_with_fds.html)
- [Default scheme handler and full-transfer ownership](https://docs.gtk.org/gio/type_func.AppInfo.get_default_for_uri_scheme.html)
- [URI support](https://docs.gtk.org/gio/method.AppInfo.supports_uris.html)
- [Strict GLib URI parser](https://docs.gtk.org/glib/type_func.Uri.parse.html), [URI flags](https://docs.gtk.org/glib/flags.UriFlags.html), [URI unref](https://docs.gtk.org/glib/method.Uri.unref.html)
- [GLib 2.72.4 GDesktopAppInfo source](https://github.com/GNOME/glib/blob/2.72.4/gio/gdesktopappinfo.c): constructor checks at `g_desktop_app_info_load_from_keyfile`; primary dispatch at `g_desktop_app_info_launch_uris_internal`. Its `get_executable` display string uses first-word extraction, so this implementation relies on GIO's constructor parsing rather than incorrectly resolving that display string for paths containing spaces.

## Bounded actual checks

`cargo test --locked -p linuxcast-platform --test applications` — eight passed on the Pop!_OS 22.04/Ubuntu-based development amd64 host with GLib/GIO 2.72.4 and Rust 1.95.0. `cargo clippy --locked -p linuxcast-platform --all-targets -- -D warnings` passed. These are actual native GIO operations under private synthetic XDG/HOME directories, not mocked launch results, browser checks or Debian session acceptance.

- Generated executable path with spaces; quoted arguments, literal shell-looking text, `%c`, `%%`, empty file/URI field codes; actual generated JSON marker proves argv and stdin EOF. Fixture stdout/stderr cannot pollute the helper protocol.
- Hidden, NoDisplay, OnlyShowIn, NotShowIn, missing TryExec, missing Exec and malformed quoting are excluded; stable paginated IDs are checked.
- Changed Exec, terminal flag, hidden/deleted entry or removed executable rejects an earlier fingerprint without creating a launch marker.
- GIO spawn failure from a nonexistent working directory returns `launch-failed`; invalid versions, extra fields, IDs, booleans/types, fingerprints, oversized and multiple frames are rejected.
- Private MIME defaults for HTTP and HTTPS launch only the generated executable with spaces. Actual markers prove a single exact URI argument, stdin EOF, and isolated stdout/stderr for encoded shell-looking text, literal `;`/`$()`, percent-encoded path/query/fragment data, IDNA, IPv4, IPv6 (including mapped addresses), custom port boundaries and the 8192-byte limit.
- Missing/changed defaults, a files-only handler and a removed handler executable report `unavailable`. Scheme-specific defaults are distinguished; a fresh helper observes a changed default. Nonexistent handler working directory reports `launch-failed` and creates no marker.
- Credential-bearing/unsupported/ambiguous URLs, invalid hosts/ports/percent escapes, literal control/whitespace/backslash/non-ASCII input, overlong URLs, protocol versions, wrong types and extra fields are refused before a valid test handler can run.

Only the fixed public Python fixture is launched. Tests clear the inherited environment, point every XDG directory and HOME at their private temporary root, use a deliberately nonexistent session bus, and remove the root afterward. No host browser, network request, desktop session, physical input or private screenshot is involved. Localized display and D-Bus activation behavior are delegated to inspected GIO source but are not exercised by these fixtures. No alternate non-desktop `GAppInfo` implementation is fabricated; its type refusal is source checked only. Browser rendering/navigation, denial and recovery on supported GNOME/KDE Wayland/X11 sessions, packaged installation and release acceptance remain pending.

Acceptance mapping: these checks support AC01 for malformed Exec and literal HTTP(S) URL dispatch without shell interpolation, and AC02 for spaces/arguments and missing/failed executables. Other typed launch actions and the full success/denial/recovery desktop matrix remain pending. UI and application-flow integration are owned by the separate application/coordinator lanes. Public synthetic fixtures support the privacy criterion; full task status remains pending coordinator integration and independent review.
