# Disposable Debian evidence runner

The S0-04 host remained unchanged after the user declined its CPU-delegation override. The successful resource/security checks instead ran in a fresh Debian guest with the required controllers available by default. This is kernel/systemd sandbox evidence, not a GNOME/KDE or physical-device release-matrix pass.

- Official image: [Debian13 genericcloud amd64,20261017-2634](https://cloud.debian.org/images/cloud/trixie/20261017-2634/debian-13-genericcloud-amd64-20261017-2634.qcow2). The included Dockerfile builds the outer lab image from the pinned F1 Debian image. Docker image ID used: `sha256:a1805464d68589e26be87a26cf7f8577a0b0dc494c88b1d14cb9cf7f155c4d10`.
- Outer container: UID/GID1000, `--cap-drop ALL --security-opt no-new-privileges --cpus 2 --memory 4g --pids-limit 512`, private cgroup/network/PID namespaces. Only the disposable lab data directory was mounted. No host home, devices, input, GPU, session socket, cgroup hierarchy, Docker socket or published port was supplied. No privileged-container flag or host-system configuration change was used.
- QEMU: `-accel tcg,thread=multi -cpu max -smp 2 -m 2048 -display none -monitor none`, writable16GiB qcow2 overlay over the checksum-verified base, NoCloud seed, virtio disks/network/RNG, private user networking and SSH forwarded only to container-loopback127.0.0.1:2222. The SSH endpoint is reachable only inside the container; no account password was set.
- Guest: Debian13.7, kernel6.12.113+deb13-cloud-amd64, systemd257.13, bubblewrap0.12.0, GCC14.2, Node24.22.1 and Bun1.4.4. Its vendor user manager already delegates `cpu memory pids`. Dependencies were installed from signed Debian repositories; the source archive and pinned F1 runtime binaries were copied into the guest. `bun install --frozen-lockfile` completed, then the documented probe/security command ran as UID1000 over SSH with a normal systemd user manager.

Reproduce on a disposable Debian13 system with those prerequisites: provision the accepted F1 Node/Bun binaries at the documented spike paths, install bubblewrap/GCC/Linux UAPI headers, copy the repository, perform the frozen install, and run `node spikes/sandbox/probe.ts` followed by `bun run test:security -- S0-04`. Confirm actual `cpu.max`, `memory.max` and `pids.max`, not merely successful `systemd-run` property assignment. The exact tested source hashes are in `../evidence/debian-source-sha256.txt`.
