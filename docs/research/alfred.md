# Alfred research and Linuxcast capability mapping

Status: research baseline and approved implementation scope. Accessed 2026-10-22. This document records public, official documentation; it is not a report of executing Alfred on macOS. Source identifiers resolve in [sources-alfred.json](sources-alfred.json).

Linuxcast implements the underlying capabilities using its own formats, runtime and Linux integrations. It does not load Alfred workflows, themes, preference bundles or snippet collections. All applicable local capabilities below belong in v1; cloud services, an online marketplace and a separate mobile remote are later work. The workflow system is specified in [workflows.md](../architecture/workflows.md), extension execution in [extensions.md](../architecture/extensions.md), and desktop support in [linux-integration.md](../architecture/linux-integration.md). Every resulting screen must follow [DESIGN.md](../design/DESIGN.md).

## Evidence and version boundary

The Alfred homepage advertised version 5.8.1 build 2349 and separately promoted Alfred 6 as an upcoming release when accessed. Use the Alfred 5 help pages as the stable behavior baseline. The Alfred 6 preview advertises a native workflow UI toolkit, optional model/API-key choice, refreshed preferences/themes/onboarding, query-history improvements and broader accessibility. These are preview claims, not a documented stable SDK or verified runtime contract. Do not infer a new executable workflow format from preview screenshots. [Homepage](https://www.alfredapp.com/) (alf-home), [Alfred 6 preview](https://www.alfredapp.com/v6/) (alf-preview).

Evidence labels used here:

- **Documented:** explicitly described by official product/help pages.
- **Linuxcast decision:** the behavior proposed for Linux; it is not attributed to Alfred.
- **Platform adaptation:** an equivalent outcome through Linux APIs rather than an Apple implementation.
- **Unverified:** undocumented internal ordering, wire formats, performance, or behavior not exercised on the original client.

### Automation-task breadth

Alfred publishes a changing task library covering appearance, argument/date/file/image/JSON/text/URL/PDF processing, application state, clipboard, browser tabs/scripts, screen capture, shortcuts, windows, Git and key simulation. Some task groups specifically target Finder, iWork, Safari and macOS. The source list is the dated inventory, not an immutable API. [Automation tasks](https://www.alfredapp.com/help/workflows/automations/automation-task/), [Current task list](https://www.alfredapp.com/help/workflows/automations/automation-task/list/).

Linuxcast's native task registry must cover these operation families in v1. The implementation specification defines Linux-native operations and adapter capabilities rather than copying task source or promising proprietary Apple application support. Examples: MIME replaces UTI classification; native tags/comments replace Finder-only metadata; browser companion replaces Safari scripting; local office-document export uses supported Linux conversion adapters. Destructive folder mirroring and Git cleanup must preview changes and require confirmation.

## Runtime behavior observed in documentation

- **Script invocation:** Alfred recommends argv instead of substituting user text into script source. It supports external interpreters and sequential/concurrent runs. Linuxcast adopts structured argv and a stricter sandbox. [Run Script](https://www.alfredapp.com/help/workflows/actions/run-script/)
- **Query execution:** script filters can wait for the prior run then use the newest query, or terminate it; delay/whitespace handling is configurable. They can run once and delegate filtering to Alfred. Keyword arguments can be required, optional or absent. [Script Filter](https://www.alfredapp.com/help/workflows/inputs/script-filter/)
- **Result contract:** rows have identity, display text, arguments, icons, validity, matching/autocomplete, file treatment, modifier alternatives, copy/large-type values and preview/action data. JSON also supports variables, reruns and caching. Linuxcast deliberately uses a different schema. [JSON result format](https://www.alfredapp.com/help/workflows/inputs/script-filter/json/)
- **State:** workflow configuration and dynamic variables are separate sources; variables can be interpolated in supported objects and are exposed to scripts through environment variables. Alfred also supplies workflow/data/cache/environment information. [Variables](https://www.alfredapp.com/help/workflows/advanced/variables/), [Script environment](https://www.alfredapp.com/help/workflows/script-environment-variables/)
- **Alternative actions:** modifiers select alternate paths and update action hints; connections can retain the launcher between input steps. [Alternative actions](https://www.alfredapp.com/help/workflows/advanced/alternative-actions/)
- **Sharing:** workflows have bundle identity, author/about/version/configuration; export produces an .alfredworkflow file. This research did not inspect an archive or derive a binary/plist importer. [Sharing](https://www.alfredapp.com/help/workflows/advanced/sharing-workflows/)
- **Typed triggers:** shared prefix/suffix, app restriction, workflow precedence over conflicting ordinary snippets; imported workflow typed bindings and hotkeys are stripped. Linuxcast chooses explicit conflicts and disabled new automatic bindings. [Snippet trigger](https://www.alfredapp.com/help/workflows/triggers/snippet/)

## Snippet and focus boundary

Alfred's macOS documentation says secure text fields are not monitored for expansion. This must not be transplanted into a Linux security claim. [Alfred auto-expansion](https://www.alfredapp.com/help/features/snippets/auto-expansion/). Linuxcast's approved native input service makes key capture/injection possible, but field sensitivity, text composition and focus remain separate capabilities.

The normative [Linux integration contract](../architecture/linux-integration.md) owns daemon privileges, keyboard recovery and desktop adapters. Workflow and snippet authors receive trigger IDs and target tokens, never global raw keystrokes. The workflow runtime must apply these rules:

1. Resolve dynamic values against an invocation snapshot, including clipboard data before Linuxcast replaces it.
2. Associate insertion with a session/seat/focus epoch and optional field epoch. Abort when that context changes; delayed results become explicit copy/paste UI.
3. Never execute workflows in the privileged input process. No extension may request an unrestricted key stream.
4. Suppress matching of synthetic output. Clear bounded matching buffers on context/input-method/layout changes and session transitions.
5. Do not conflate Unicode snippet output with reliable Unicode trigger recognition. Test direct layouts, dead keys, Compose and IME committed text independently.
6. Do not blindly restore an old clipboard over a newer copy. Ownership changes, delayed readers and clipboard-manager reoffers are explicit test cases.
7. Reject overlapping immediate-trigger prefixes and duplicate enabled keywords in overlapping app scopes.
8. Preserve a manual library/search/copy path whenever automatic expansion is paused or unsupported.

## What this research does not establish

No original application binaries were executed or decompiled. Internal scheduling order, undocumented crash recovery, memory use, exact ranking weights and undocumented package internals remain unknown. Screenshots and text describe behavior, not implementation internals. The third-party Gallery is open-ended: capability support does not mean every vendor workflow has been ported or its service credentials supplied.

The future Alfred 6 toolkit has no stable contract established by this research. Native Linuxcast ViewModels provide the approved UI extension seam now. Design and implementation acceptance must be based on this repository's contracts, measured Debian behavior and the canonical design document, not assumptions of perfect macOS parity.
