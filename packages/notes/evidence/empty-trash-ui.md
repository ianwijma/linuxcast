# Confirmed whole-Trash Notes UI increment

30 October 2026, isolated `codex/notes-empty-trash-ui` on PR75 `a8ad162`. Partial U1-01 application implementation; F2-01 is accepted, while broader D1/native prerequisites remain unfinished under the authorized sequencing.

Show trashed notes now exposes **Empty Trash**. Its explicit read captures the whole-Trash count/fingerprint, independently of search, pin/archive flags and list pagination. The shared confirmation defaults to **Keep notes**, traps Tab between the choices, cancels on Escape and requires a separate **Empty Trash permanently** activation. It discloses all-count scope, retained saved revisions, no undo here, backups and no secure-erasure claim. Dirty/pending/uncertain states refuse admission; preparation/cancel never flush or write. Existing individual deletion remains separate.

The controller reserves prepare/confirm/effect/recovery before notifying subscribers. Exact receipt alone clears a selected trashed source; an active editor remains exact. The filtered library refreshes without selecting a fallback. A caller deadline retains the actual effect slot; late settlement cannot acknowledge success. Unknown keeps the view and blocks Close/export/Quick/selected-open/mutations until deliberate **Reload Trash** after settlement obtains a whole snapshot and selected-source read. Missing obsolete selection clears informationally without claiming the unknown deletion succeeded or replaying it. Known refusal requires a new read and confirmation; unavailable capability has reconnect guidance.

Design: `docs/design/DESIGN.md` sections Tokens, Chat and notes, States and motion, Accessibility and Review gate. Uses existing Notes layout/recovery surface, shared Button/TextField/ThemeProvider/focus restoration and token CSS; no new visual system.
